Federated Architecture

Each service is its own page, repo, and expansion module.

The menu links are deliberately external. The first Aurora Nest page is the gateway. Every service page can later become its own full website while keeping the same zero-point hamburger navigation spine.

Repository Structure

The master repository is Aurora Nest. Future service repositories are separate GitHub Pages sites. The master menu points to them before they exist. A temporary 404 is expected until each repository is created and published.

Why this works

Each module can be built independently, audited independently, deployed independently and still feel like one coherent website through the shared hamburger navigation.

Build Order

  • Create Aurora Nest repo.
  • Add this file as index.html.
  • Enable GitHub Pages.
  • Open the live URL.
  • Create each missing service repo when ready.

Expansion Rule

Copy the same topbar and hamburger menu into every future service page. That keeps the zero-point navigation consistent across the entire federated website.

Audit note: The menu uses real external URLs generated in JavaScript. Update the GitHub owner and repository slugs before deployment if your GitHub username or repo names differ.
